## Architecture

**Mechaavo customer-facing landing page** — Next.js 16 App Router, React 19, Tailwind v4, GSAP 3.

### Page structure

Single route: `app/page.tsx` → `MechaavoHero` + `ProductCategories` + `BrandStory`. Sections and their ids live in `lib/config/sections.ts` (`#categories`, `#story`, `#principles`, `#commitment`); the nav links and the hero CTA come from the same file so no two links share a target.

**Jumping to a section (nav links, the hero CTA, the bar's logo).** A plain `<a href="#id">` would cut across about nine screens of pinned, scrubbed stages (the hero track, then the categories card), so the jump dips through the page's own white instead: `components/ui/SectionJumps.tsx` (a leaf mounted once in `app/page.tsx`, the markup is the veil), `lib/animations/sectionJump.ts` (a delegated click listener, framework-free) and `src/styles/section-jump.css` (`.section-veil`: one fixed `--page` layer, `opacity: 0`, `pointer-events: none`, layer `--z-veil`). A click fades the veil in over 260 ms, the browser does the jump while it is covered (`location.hash = id`, so history, `:target` and the next Tab stop are native; a hash it already has is scrolled to with `scrollIntoView`, because the browser ignores that case), then the veil lifts over 420 ms as the target's Tide headings start. Opacity on one layer only, nothing lays out (CLS 0). Only the ids in `SECTION_IDS` are handled (the skip link is not), and a link to this page's own address (the bar's logo) goes to the top the same way (not when already at the top); the listener is in the capture phase, because `next/link` skips a click something has already handled. A second click mid-way picks the veil up where it is, and Cmd / Ctrl / Shift / Alt / non-primary clicks fall through to the browser. **Fallbacks:** no script and reduced motion = the plain anchor's instant jump; forced colours = a `Canvas` veil. A fast scroll was rejected on purpose: it would play the catch and the card opening at ten times speed on the way. New in-page links need only an id in `SECTION_IDS`.

**Sticky nav bar (the hero nav's second state).** The nav used to exist only in the hero, so a jump to a section left the reader with no nav. `components/ui/SiteNavigation.tsx` (mounted once in `app/page.tsx`), `src/styles/site-nav.css`, links `SITE_NAV_LINKS` in `lib/config/sections.ts` (Categories plus the three nav links). A fixed bar, 64 px (52 px under `(max-height: 34rem)`), the page white with a hairline, the hero's fold (Menu button under 768 px, inline links from there, the same cast plate and 44 px touch targets). It slides in (300 ms, out 200 ms; reduced motion: no slide) once `#story` has reached the top of the screen and out when it leaves, so it is **absent** over the hero (its own nav is there) and over the full-screen categories stage (it would cover the catalog's header). Hidden it is `inert`, so only one nav is ever exposed to the keyboard and screen readers (landmarks "Primary" and "Sections"). Layer `--z-bar`, above the jump veil: a jump dips the content while the bar stays put. **Gotcha, fixed:** do not observe `#story` alone to decide "past the start of the story": a jump from the hero to `#principles` never makes `#story` cross the strip, so the observer never fires. The component observes all three story sections (they tile the page from `#story` to its end) and re-reads `#story`'s position on any change. Without script it is `display: none` (the hero nav is a plain row there). Registered as the revision of D11. The old hero nav stays untouched: the engine measures its logo for the lure's swim-in and the hover bubbles.

### Theme, color, type

The site has one theme: **white** (client decision). Three layers, each in one place:

- `src/styles/theme.css` is the **only** file allowed to contain raw color values — eight tokens total.
- `src/styles/roles.css` maps *roles* (`--page`, `--page-alt`, `--ink`, `--ink-soft`, `--ink-muted`, `--line`, `--accent`, `--on-accent`) onto those tokens. Components use roles (`bg-page`, `text-ink`, `border-line`, `bg-accent`) rather than naming dark or white, so re-theming is a change in this one file. `globals.css` exposes roles and tokens to Tailwind through `@theme inline`; Tailwind's default palette and stock shadows are wiped (`--color-*`, `--shadow-*: initial`).
- Tailwind scans only `app/`, `components/` and `lib/` (`@source` in `globals.css`, `source(none)`): scanning the repo would pull the example classes in `.agents/` (raw `rgba()` shadows) into the compiled CSS. After a build, the compiled CSS should hold only the eight token hexes (plus Tailwind's `#0000` = transparent).
- Canvas code reads the same tokens at runtime via `lib/theme/brand.ts` (`readBrandPalette()`: `alpha()`, `solid()`, `rgb()`), which resolves the CSS custom properties. That file holds the one `rgba(` string builder.
- Type is Raleway only, configured in `lib/config/fonts.ts` (`next/font/google`, variable font, `--font-raleway`); `globals.css` maps `--font-sans` to it. There is no other font and no mono. Raleway's default digits are old-style, so the body sets `font-variant-numeric: lining-nums`.
- The logo's source is `public/images/mechaavo-logo.jpeg` (two waves plus the MECHAAVO wordmark; off-palette blue and a red E). The client asked for it exactly as supplied, so it is shown in its OWN colours (the one asset exception to the eight tokens; CSS and canvas stay token-only): `docs/make-logo-assets.mjs` turns the JPEG into true-colour transparent PNGs (`mechaavo-logo-mark.png`, `mechaavo-logo-lockup.png`) and a white-square favicon (`app/icon.png`), and `components/brand/BrandLogo.tsx` renders them with `next/image`. The hero nav and the story section both show the full lockup (waves plus MECHAAVO wordmark; the nav logo is at most 128 px wide, `.hero-nav__logo`, so the bar stays at most 80 px). The mark's alpha is still the faint watermark behind the story headline (filled with a token). Under 768 px the three nav links fold into a Menu button (`HeroNavigation.tsx`: Escape, outside press and link click close it) because they cannot sit beside the logo; without script the CSS lays them out as a row under the logo instead. To change the logo, replace the JPEG and rerun the script (then update the two `aspect-ratio` values it prints in `src/styles/brand.css`).

### Heading system (Tide)

Every heading on the site is one system: `components/ui/Tide.tsx` (markup, no hooks, works in server and client components), `src/styles/tide.css` (look and motion), `components/ui/TideObserver.tsx` (a leaf mounted once in `app/page.tsx`). Use it for any new heading instead of colouring text by hand.

- **Colour, within the 8 tokens.** On white the brand blues are 2.4:1 and 1.9:1 and cannot carry text, and the letters stay dark; colour comes in around them. (1) The **plate**: the payoff word of a heading sits on a gradient from `--color-primary` to `--color-accent-secondary`, skewed -9deg, with ink text on it (8.1 to 8.2:1 measured). (2) The **letters** are ink dipped in the water: a vertical gradient from `--color-dark` toward `--color-primary` whose blue stop lies past the end of the glyphs, so the baseline only gets about 40% of the way (5.9:1 and better measured at the baseline). A quieter second line uses `--color-secondary` at 84%. (3) The **drop**: the full stop is a blue circle that falls onto the baseline, squashes, springs back, and sends two flat ellipse ripples in `--color-accent-secondary` (the lure's splash, in miniature).
- **Markup.** `<Tide as="h2" text="Great products don’t happen by chance.|They are engineered with [purpose]." drop muted={[1]} />`: `|` is a line break, `[words]` the plate, a final `.` becomes the drop when `drop` is set. Words are real inline text with real spaces (copy, find-in-page and screen readers read plain text); the plate and drop are `aria-hidden`. `Mark` and `Drop` are exported for hand-built markup (the hero lines, whose arrival is CSS from first paint and whose `data-hero` hooks the scroll timeline moves).
- **Motion** (transform and opacity, plus one paint-only custom property): words rise out of their masks (`clip-path`, not `overflow: hidden`, which would move the baseline) 55 ms apart; the plate wipes in behind the payoff word; a glint of light crosses it once; the drop lands; the water level in the letters (`@property --tide-dip`) rises. Plays once, when the heading first scrolls into view (`TideObserver` sets `data-inview`); hovering a landed heading on a pointer device replays the glint and ripples. Nothing loops.
- **Starting it.** The observer for headings on the page; `inview` for one that appears on demand (the inspector's name); `manual` for one shown by something other than scrolling: the catalog's heading waits until the card is half open (`categoriesTimeline.ts` sets `data-inview`; the component's load-failure path sets it too). The hero title starts with `data-inview` from first paint; the hero statement's plate and drop start off `data-caught`. A plate that opens a line hangs into the margin (`tide__mark--lead`) so the text keeps the column's edge.
- **Fallbacks, each tested.** No script, or reduced motion: every heading is finished (plates open, drops down, nothing held back). Held back only under `(scripting: enabled) and (prefers-reduced-motion: no-preference)`. If hydration fails and the observer never starts, a CSS failsafe shows every heading after 3 s (`html:not([data-tide-ready])`). Forced colours: system colours, no gradient. A heading's real `color` is still ink, so tools and forced colours see ink.
- **Verified 2026-10-02:** 38 checks (behaviour, static fallbacks, failsafe, pixel-measured contrast, no overflow from 320 to 2560 px, CLS 0.0000 while every heading plays); Lighthouse accessibility 100 on mobile and desktop.

### Button plate (the "cast" plate on every button)

Every button wears the heading's plate on hover: `src/styles/tide-button.css`, class `tide-btn`, no markup, no JS. The button's `::before` is the plate (same gradient, `--tide-skew` and curve as the headings; `--tide-skew` now lives on `:root`), its `::after` the glint (Tide's `tide-glint-again` keyframe); `overflow: hidden` clips both to the button's own shape. Hover, keyboard focus, a press, or (menu button) `aria-expanded="true"`: the plate wipes in over 420 ms, the glint crosses once after it lands, the label turns ink (white on the blue plate is 2.4:1, ink on it 8:1). Leaving retracts the plate the way it came in 260 ms (no origin switch, so an interrupted hover never jumps). Timings are tokens at the top of the file (`--btn-in`, `--btn-out`, `--btn-ease`, `--btn-color`).

- **Rules for a new button:** add `tide-btn`; make sure it is positioned (the static ones set `position: relative` in their own rule, because a `position` in the shared rule would beat Tailwind's `absolute`); if it has its own `transition` list keep `color var(--btn-color)` in it (otherwise the label flips before the plate covers it); put no `:hover` background of its own on it (the plate is the hover). Keep each button's own lift or `:active` push (hero CTA lifts, the rest scale to 0.96-0.98).
- **Touch:** `:hover` is only used under `(hover: hover)`, so a tap never leaves a stuck plate; on touch the plate shows on `:active` and while the menu is open. Reduced motion: no wipe, no glint, the plate fades in over 150 ms. Forced colours: no plate, a `Highlight` outline. No script: unchanged (CSS only).
- **Who wears it:** hero CTA, the four nav links (padding with an equal negative margin, so they sit where they did), the mobile Menu button, both pause / play buttons, the modal's close and Done buttons. The category tiles keep their lift and border and put the plate on the **name's last word** (Tide's `Mark`, closed until the tile is touched; `categories.css`). The logo link is an image, not a button, and keeps its bubble stream.
- **Not added on purpose:** the drop and its ripples. Wipe, glint and the label flip already carry the state change; more would be motion for show.
- **Verified 2026-10-02 (clone build):** every button hovered frame by frame (wipe, glint, ink label, retract), rect identical hovered vs not (apart from each button's own lift), CLS 0, keyboard Tab through all, touch (no stuck hover, `:active`, menu open / close), reduced motion, forced colours, no script, nav one line and CTA one line from 320 to 2560 px, Lighthouse accessibility and best practices 100 on mobile and desktop, compiled CSS still only the eight token hexes.

### Hero system

The hero is a cinematic, scroll-driven underwater scene (bright, sunlit water on the white page). Concerns are kept deliberately separate:

0. **Sticky track, no JS pin.** `MechaavoHero` renders `.hero-track` (a tall element, 6.1 screens on landscape, 5.2 on stacked, set in `underwater.css` only when scripting is on and motion is allowed) and the hero is `position: sticky` inside it. The categories section (`.story-sheet`, `ProductCategories.tsx`) is pulled up one screen over the end of the track like a curtain, so the hero is never replaced by a blank screen: the catch, the statement and the water stay in view until the page's own ground rises over them. The timeline is scrubbed over `track height - 2 screens`; `HeroScene.covered` (a ScrollTrigger on `#categories`) lets the engine rest while the sheet hides the hero. Reduced motion: no track, no curtain, one still screen.

1. **DOM + GSAP (`lib/animations/heroTimeline.ts`)** — one scrubbed `ScrollTrigger` timeline (100 units long). It tweens DOM elements (headline, rays, haze, camera push-in) and the shared `HeroScene`. All elements are located by `data-hero="<key>"` attributes, not React refs or class names. It deliberately does **not** drive the fish, the lure's own motion, the catch, or the brand statement.

2. **Canvas engine (`lib/underwater/engine.ts`)** — framework-free. Reads `HeroScene` every rAF tick; never touches React state. Two stacked canvases (`UnderwaterCanvas.tsx`): a fish is drawn on whichever side of the lure's plane (`Z_LURE` in `pose.ts`) it is on. Far foreground fish are drawn into a small buffer and upscaled (cheap blur): upscale only the drawn region with `imageSmoothingQuality = "low"` (a full-screen "high" resample cost ~70 ms a frame at 2x). Frame order: advance the water's current, step the lure rig and write it to the DOM, measure the lure's anchors, step the fish against that, react to bites, draw. The engine tells the page about the catch with `data-caught` on the hero root (set at the bite, cleared on a release) and about the lure with `data-lure`; the brand statement ("Precision creates possibility") is a plain CSS transition off `data-caught` (`underwater.css`), so it arrives with the bite whatever the scroll speed. It is unseen by opacity, not visibility, so screen readers and search still get the words. While the story sheet fully covers the hero the hero is `inert`, so its nav and call to action take no focus from under the sheet.

3. **`HeroScene` (`lib/underwater/story.ts`)** — plain mutable object (never React state). The timeline writes `story` (0–1 master progress), `engage`, `flow`, `zoom`, `descend`, `copy`, `reel`; the engine writes `calm`, `statement`, `covered`. `calm` and the fight are on the fish's own clock (time since the bite), never the scroll, so a fast scroll cannot skip or cut short the fight.

**One water current for everything (`lib/underwater/current.ts`).** A slow uneven push (leftward, nose of the lure into it) drives the lure's float, the bow and ripple of its line, the weed (`seabed.ts` draws blades live), the sediment motes (`particles.ts`) and the bubbles, so they lean and ease on the same beat. Do not give any of them a private sway.

**Fish are time-based, not scrubbed.** Scroll only decides *what* the primary fish is doing (`story` thresholds in `story.ts`, with hysteresis); every move is made at the fish's own speed in body lengths per second.
- Sizes come from the lure. The lure is small (about 14% of the width, `.hero-lure-slot` in `underwater.css`); the hero fish is `FISH_TO_LURE` (`lib/hero/lureConfig.ts`) lure lengths long, and every fish at or in front of the lure's depth (mid, near, visitors) is at least a lure long (`fish.ts` sizes tiers in lure lengths). A lure is never bigger than the fish. Do not cap `world.unit`.
- How many fish of each kind there are depends on the screen (`lib/underwater/quality.ts`, tiers phone / tablet / laptop / desktop / wide). The counts and the fish-to-lure ratio are hand-tuned by the client; read them from the file rather than from this note, and if a screen looks cluttered cut big fish, not small ones. Big fish keep a corridor of clear water around the lure (`laneBands` in `fish.ts`); weed density also follows the tier.
- Primary fish (`primaryFish.ts`): `patrol → notice → inspect → circle → windup → strike → hooked`, plus `release` when scrolling back. It swims in from the left edge once the lure has arrived. **The lure tracks the fish**: the first notch of the wheel sets `scene.lead` rising and the lure drifts down the current to just ahead of the fish's nose (the engine follows the nose while the fish patrols, then holds the spot once the fish notices it; `rig.trackGoal*`). While patrolling, the fish measures its position from the lure's *resting* hook (`PrimaryBrain.frame` 0) so it keeps to its own water; from `notice` on it measures from the live hook (frame 1), re-based so nothing jumps. It bites quickly (notices on the first notches, strikes at about a seventh of the way through the scroll, short dwells). If scroll runs three or more steps ahead it **dashes** (every step hurried until it catches up), so a flick still shows the whole catch in about two seconds. **The bite takes the whole lure**: the strike lands on the belly hook exactly as before (its path and timing are client-approved: do not move them earlier), then for `GULP_SECONDS` of `hookedTime` the mouth slides forward over the lure to just past its nose (`applyFight`, measured live from the lure's anchors; `brain.gulp` 0–1), jaws wide then closing, so the lure ends up inside the fish and the line leaves its lips. On a release `gulp` eases back to 0 and the lure comes back out. The fight feeds the lure rig (`pull`, `shake`). After `STORY.reelStart` more scroll draws the hooked fish **up out of the water** along the line (`scene.reel`; the engine gates it until the fish has fought a while and eases it, so a fast scroll still shows the bite first). The hooked fish keeps a natural, near-horizontal heading (client-tuned in `applyFight`; do not tip it vertical).
- Ambient fish: lane crossers, baitfish schools, and a visitor on a tilted loop around the lure; speeds 0.45–2.8 body lengths/s, tail beat follows speed, pitch clamped, depth turns only.

**Lure rig (`lib/underwater/lureRig.ts`).** The engine owns the lure's `pull` and `shake` DOM layers plus the jointed parts of `LureArt.tsx`. `pull` carries the whole lure (float, tilt about the nose, size). The lure *floats*: position springs forced by the shared current plus a twitch every 5–9 s, the pendulum tilt, jointed tail wag, hooks on rings. The tail treble is dressed with a feather tuft (`dress` and `dress-tip` parts, nested in the treble, with their own springs: it swings with the treble and flutters on the current's gusts; a worm trailer was tried and dropped, hard baits do not carry one). On arrival it swims in from the nav logo (its waves, `LOGO_MARK_Y` in the engine) along a bezier (small and growing, nose along its path) with a bubble trail and a small splash (`bubbles.ts`: two rings and spray). Anchors ride inside the parts that move them so the fish and the line stay on the real hook. The line (`drawLine` in the engine) is a flexible thread from the nose to a fixed rod tip far up the frame: it bows downstream with the gusts, ripples, sags when slack, goes straight and trembles when a fish is hooked; at least 1.6 px of dark core so it is always visible. Once a fish has drawn the lure into its mouth the lure fades out (`gulp` in `readRigPose`; the two trebles and the feather, which hang outside the fish, fade first): **by opacity only, never size or position**, because the engine measures `lure.length` and the anchors from the DOM every frame and sizes the fish from them. The lure body is fully opaque (solid underlay, no transparent gradient stops) and sits above the caustic light and below the copy. Writes are CSS transforms only. Never animate those layers from GSAP.

**Load order matters for performance.** The headline, nav and supporting copy arrive with CSS keyframes in `src/styles/underwater.css` (transform-only on the text); the lure stays hidden until the engine sets `data-lure` (with a CSS failsafe after 5 s and a no-script fallback). GSAP/ScrollTrigger and the canvas engine are dynamically imported and started when the browser is idle (`lib/utils/idle.ts`), and the caustic tile is built in slices. Do not move the arrival back into GSAP or statically import either. On a throttled phone the Largest Contentful Paint is the tagline re-rendering when Raleway swaps in, so keep first-load bytes and early main-thread work low.

**Layout.** `.hero-stage` (nav, copy, lure, captions) shares `.page-container`'s max-width and gutters (`--page-max`, `--page-pad` in `globals.css`). Layer order lives in the `--z-*` scale at the top of `underwater.css` (water, light, back canvas, caustics, lure, copy, front canvas, statement, captions, nav); never hard-code a z-index. Hovering or focusing the logo sends a stream of bubbles (`emitStream` in `bubbles.ts`, 1.6 s cooldown) from its waves, aimed at the lure so it flows across the screen; sized by the screen, not by the lure. The statement sits upper left, the fight plays out right and below. Headline voice is `.display-type`, in the colours of the heading system (see Heading system): the title's plate and drop follow its lines in, the statement's follow the catch.

**Short screens and the nav.** The hero is exactly `100svh`, with no `min-height`: one taller than a short screen pushed the CTA and the captions below the fold for good. Under `(max-height: 34rem)` (a phone on its side, a very short window) the nav slims, the type is sized from the height as well as the width (`min(4.6vw, 11svh)`), the lede and the statement's sub-line fold away and the CTA keeps its 44 px; the story itself is untouched. Landscape phones narrower than 768 px get the stacked layout (`isStacked`), wider ones the split layout; on a short landscape screen the lure's slot is the split one in both (right of the copy), since the stacked slot would put the lure under copy that fills the screen. Without script the nav links form a row under the logo (two rows on a 320 px phone), and the copy starts below them. The hero nav lists three links (the hero CTA is the one door to `#categories`; the nav is only on screen while the hero is, the sticky bar below takes over from `#story` on), the bar is at most 80 px, and on a coarse pointer (a tablet) the links get 44 px targets 8 px apart by the same negative-margin trick, so the bar never grows.

`MechaavoHero` owns the `scene` object (via `useState`) and calls `createHeroTimeline` inside `gsap.matchMedia`. Rebuilds when the layout switches between *split* (landscape) and *stacked* (phones and any portrait viewport, incl. tablets; `STACKED_QUERY` in `quality.ts`, which must stay in sync with the media queries in `underwater.css`); skipped for `prefers-reduced-motion` (one still frame, lure at rest, no swim, no splash).

### Lure asset

`lib/hero/lureConfig.ts` defines the expected path (`public/images/mechaavo-hero-lure.png`), anchor fractions, the fish-to-lure size ratio and the fishing-line angles (steeper on stacked layouts so more of the line stays in frame). `lureAsset.server.ts` reads only the PNG header at build time and returns `null` if the file is absent or its color type cannot carry alpha; `HeroProduct` then probes the four corners client-side and rejects a boxed (opaque-corner) photo. Either way the fallback is the procedural jointed lure in `components/hero/LureArt.tsx` — a boxed image is never shown. A real cut-out keeps the whole-lure physics and a drop shadow; the joints and hooks only exist on the vector art. When a real product cut-out lands, retune `LURE_ANCHORS` in `lureConfig.ts` to match.

### Categories section

`components/showcase/ProductCategories.tsx` is the curtain over the hero (`id="categories"`, class `story-sheet`, the swell `.story-edge`; `heroTimeline.ts` finds it by that id) and the second block of the page: a portrait card of water that opens to fill the screen. Look and layout are in `src/styles/categories.css`; the scrub is `lib/animations/categoriesTimeline.ts`.

- **One set of elements, two layouts.** The scrolling layout applies only under `(scripting: enabled) and (prefers-reduced-motion: no-preference)` (the hero's gate): `.cat-track` (the section) is `--cat-screens` (3) viewport heights tall and `.cat-stage` sticks inside it, no JS pin. Otherwise (no script, reduced motion, or GSAP failed to load: the component then sets `data-static` on the section) it is a plain block: water behind, catalog in the flow, the white preview card `display: none`. Nothing is hidden by default without that fallback.
- **The card is one number, and nothing in the layout moves.** `--open` (0 = closed portrait card, 1 = full screen; registered with `@property`, set on four elements that each read it: `.cat-frame`, `.cat-shadow`, `.cat-media`, `.cat-toggle`). The frame is the whole stage the entire time and the card is a **window cut in it** (`clip-path: inset(... round)`, insets in percent of the frame minus `--card-w` / `--card-h`, radius from `--card-r`): `clamp(360px, 44vw, 560px)` capped to the page column on phones, `clamp(480px, 64svh, 660px)`, 36px. The water behind the window scales from the size that just covers the closed card (`--s0`, found with `tan(atan2(card, stage))`, CSS's way to divide one length by another) to 1; the pause button rides to the corner with `translate`; the shadow is its own card-sized layer (a clip-path would cut it off) that is gone once the window is open a little. **Why not width / height:** growing the card that way counted as layout shift on every frame of the scroll, a CLS of 0.25 (0.16 on a phone) over a scroll through the page, which Lighthouse never shows because it never scrolls. Now it is 0.0000, with zero layout during the opening. Test it by scrolling the whole page with a `layout-shift` observer, not with Lighthouse.
- **Timeline** (100 units over the track, elements by `data-cat="<key>"`): 0-8 hold, 8-56 `--open` 0 to 1, 8-32 the white preview scales to 0.88 and fades, 38-60 the catalog fades in, the rest is a hold so the catalog can be used before the stage lets go. Opacity goes on the glass element itself, never an ancestor: an ancestor with opacity below 1 makes the `backdrop-filter` blur pop on at the end instead of fading in. Reversible by construction.
- **Water.** The same grayscale loop as the story panel (`CATEGORIES_VIDEO` in `lib/config/media.ts` points at the same files; a dedicated clip is a one-line swap there), mirrored, graded with tokens (multiply onto `--color-primary`, white lift, dark scrim). The controller is `lib/hooks/useLoopingVideo.ts`, shared with `StoryVideo`: lazy near the viewport, rendition measured at the *viewport* width (the card ends full-bleed), plays only while visible, poster under reduced motion, pause / play button above the glass.
- **Design review.** The taste and ui-ux rules, already reconciled with this brief, are in `docs/DESIGN-GUIDELINES.md` (imported at the top); every deliberate deviation of this section (the badge and its pulsing dot, the scroll-cue subtitle, "System 02", the index numerals, the rounded 36 / 28 / 16 px family, `svh`, white only, eight equal tiles) is registered there as D6, D7, D2, D4 and restated by id, and every skill rule is mapped in `docs/design/rule-map.md`. Run the gates instead of re-reading the skills. ("CATEGORIES." is ink on the heading plate, not accent text; the opening animates only `--open`, never width or height.)
- **Catalog.** Frosted glass (`.cat-catalog`) holding the header and the eight tiles; the `CATEGORIES` data and the inspector dialog live in the component (Escape closes it, Tab stays inside, focus returns to the tile). Tiles are compact (index, name, action) below `lg` so all eight fit a phone, and a short screen at least 640 px wide gets two rows of four; the catalog scrolls inside itself as a fallback on very short screens. Do not put `overscroll-behavior: contain` on it: scroll must still chain to the page. **Keyboard and screen readers:** the catalog is hidden by opacity, never `visibility`, so the tiles stay in the tab order and the accessibility tree at any scroll position; it takes pointer input from `data-open` (the timeline sets it at half the scrub), and focusing a tile scrolls the page into the hold so the card opens (`categoriesTimeline.ts`). **Measuring:** the stage is a size container, so the card's calc()s use `100cqw`, never `100vw` (which includes the scrollbar). **The dialog** uses `max-height: 90dvh`, `overscroll-behavior: contain`, a sticky zero-height close row (`.cat-modal__close-row`) and its layer in `--z-modal` (page-level layers are `--z-sheet`, `--z-modal`, `--z-veil`, `--z-skip` in `globals.css`).

### Story section and video

`components/showcase/BrandStory.tsx` holds three sections with three different layouts, each text block at most 25 words. The first (`#story`) opens with the water the categories sheet ends in (`--story-edge` is defined on `:root`: a `top` water light that cannot see it loses its whole wash); every section has water behind it (`WaterLight.tsx`: `top` = the hero's water clearing into the page with the brand mark as a watermark and the hero's caustic light drifting on it, `soft` on the gray band, `bottom` at the foot of the page). Nothing downloads until the panel is within ~400 px of the viewport; it plays only while visible, stays on its poster under reduced motion, and always has a pause/play button (all of that is `lib/hooks/useLoopingVideo.ts`, also used by the categories card).
