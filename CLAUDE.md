## Commands

```bash
npm run dev      # dev server on localhost:3000
npm run build    # production build (never in the repo while `next dev` runs: it owns .next; see design:sweep)
npm run lint     # eslint
npm run design:lint                # static design lint (rules in docs/DESIGN-GUIDELINES.md); also runs from the edit hook
npm run design:sweep -- --build    # production COPY on :3150 + 29-screen browser sweep (gates G1 to G17), then stops it
npm run test:ui                    # Playwright (@playwright/test, system Chrome): UI cross-check + fluency on 6 screens, on a production COPY on :3350
npm run test:ui:fluency            # only the frame-pacing spec;  npm run test:ui:report  opens the HTML report (screenshots, metrics JSON, the recorded scroll)
```

The Playwright suite (`playwright.config.ts`, `e2e/`) is the round-by-round cross-check of what the client sees: `e2e/ui.spec.ts` (the ocean's hue and the Mechaavo-blue fish sampled from screenshots, copy contrast by pixel sampling, the categories arriving after the bite with bubbles, section rhythm, 4K scaling, keyboard, reduced motion, no script, CLS) and `e2e/fluency.spec.ts` (real-input scroll through the whole page, per phase frame time p50/p95/p99, jank, long animation frames, CLS; phones and tablets at 4x CPU throttle, median of 3 runs; budgets are a report (a miss is noted, twice the budget fails), CLS is hard) plus `e2e/recording.spec.ts` (a video of one scroll). `E2E_BASE_URL=http://localhost:3000` points it at a running server (dev-mode timing is not representative); `E2E_PORT` and `E2E_KEEP=1` as in `e2e/global-setup.ts`. Expected colours come from `src/styles/theme.css` through `e2e/helpers/color.ts`, so the tests never keep a copy of the palette. The design lint has `--self-test` (`node scripts/design-check.mjs --self-test`).

## Architecture

**Mechaavo customer-facing landing page** — Next.js 16 App Router, React 19, Tailwind v4, GSAP 3.

### Page structure

Single route: `app/page.tsx` → `MechaavoHero` + `ProductCategories` + `BrandStory` + `ContactSection` inside `<main>`, then `SiteFooter` after it. Sections and their ids live in `lib/config/sections.ts` (`#categories`, `#story`, `#principles`, `#commitment`, `#contact`); the nav links and the hero CTA come from the same file so no two links share a target.

**Contact and footer.** `components/showcase/ContactSection.tsx` (`#contact`, on the gray band, heading "Get in touch.", one line, then the ways to reach the brand as whole-tile links that wear the cast plate: compact rows on a phone, a 2-column grid from sm, 4 columns from xl; `src/styles/contact.css`) and `components/ui/SiteFooter.tsx` (logo, one line, the social profiles, the copyright; the page ends in the `bottom` water light, which moved there from `#commitment`). Both read `lib/config/contact.ts`: **its values are placeholders** (`CONTACT_IS_PLACEHOLDER = true`, example.com style) because the brand's real details are not in the repo; a field set to `null` is not shown, and `design:lint` warns (`contact-placeholder`, `--strict` fails) until the real ones are in and the flag is false. The footer does not repeat the section links (the sticky bar is on screen from `#story` on): social profiles live only in the footer, so no two links share a target.

**Jumping to a section (nav links, the hero CTA, the bar's logo).** A plain `<a href="#id">` would cut across the hero's scrubbed story (the catch, the reel, the camera sinking under the catalog), so the jump dips through the page's own white instead: `components/ui/SectionJumps.tsx` (a leaf mounted once in `app/page.tsx`, the markup is the veil), `lib/animations/sectionJump.ts` (a delegated click listener, framework-free) and `src/styles/section-jump.css` (`.section-veil`: one fixed `--page` layer, `opacity: 0`, `pointer-events: none`, layer `--z-veil`). A click fades the veil in over 260 ms, the browser does the jump while it is covered (`location.hash = id`, so history, `:target` and the next Tab stop are native; a hash it already has is scrolled to with `scrollIntoView`, because the browser ignores that case), then the veil lifts over 420 ms as the target's Tide headings start. Opacity on one layer only, nothing lays out (CLS 0). Only the ids in `SECTION_IDS` are handled (the skip link is not), and a link to this page's own address (the bar's logo) goes to the top the same way (not when already at the top); the listener is in the capture phase, because `next/link` skips a click something has already handled. A second click mid-way picks the veil up where it is, and Cmd / Ctrl / Shift / Alt / non-primary clicks fall through to the browser. **Fallbacks:** no script and reduced motion = the plain anchor's instant jump; forced colours = a `Canvas` veil. A fast scroll was rejected on purpose: it would play the catch and the card opening at ten times speed on the way. New in-page links need only an id in `SECTION_IDS`.

**Sticky nav bar (the hero nav's second state).** The nav used to exist only in the hero, so a jump to a section left the reader with no nav. `components/ui/SiteNavigation.tsx` (mounted once in `app/page.tsx`), `src/styles/site-nav.css`, links `SITE_NAV_LINKS` in `lib/config/sections.ts` (Categories plus the three nav links). A fixed bar, 64 px (52 px under `(max-height: 34rem)`), the page white with a hairline, the hero's fold (Menu button under 768 px, inline links from there, the same cast plate and 44 px touch targets). It slides in (300 ms, out 200 ms; reduced motion: no slide) once the categories section (rising over the pinned hero) has come up to the bar's line (its own height plus 2% of the screen) and out when it leaves, so it is **absent** over the hero (its own nav is there); the categories are an ordinary section now, so the bar no longer steps aside for them (the card it used to avoid is gone). The hero turns `inert` on the same line (`heroTimeline.ts`), so exactly one nav is exposed at a time. `html { scroll-padding-top: var(--bar-h) }` keeps anchors and focus below the bar. Hidden it is `inert`, so only one nav is ever exposed to the keyboard and screen readers (landmarks "Primary" and "Sections"). Layer `--z-bar`, above the jump veil: a jump dips the content while the bar stays put. **Gotcha, fixed:** do not observe the first section alone to decide "past the start": a jump from the hero to `#principles` never makes `#categories` cross the strip, so the observer never fires. The component observes every section from `#categories` on (they tile the page to its end) and re-reads `#categories`' position on any change; the strip follows the window's height (resize). Without script it is `display: none` (the hero nav is a plain row there). Registered as the revision of D11. The old hero nav stays untouched: the engine measures its logo for the lure's swim-in and the hover bubbles.

### SEO

`lib/config/site.ts` holds the site's address, title, description and Search Console token. **Its `url` is a placeholder** (`SITE_IS_PLACEHOLDER = true`, the site is not live): `design:lint` warns (`site-placeholder`, `--strict` fails), and while it is true the page has **no canonical** (a canonical at a stand-in address would tell Google the page lives there). `app/layout.tsx` (`metadata`: `metadataBase`, title template, description, Open Graph, X card, verification), `app/robots.ts`, `app/sitemap.ts` (one URL; add new routes), and the JSON-LD in `app/page.tsx` from `lib/seo/structuredData.ts` (Organization and WebSite; social and contact join only once `CONTACT_IS_PLACEHOLDER` is false; no Product markup without real offers and confirmed specs) all read it. The share image is `app/opengraph-image.jpg` plus `.alt.txt`, a reduced-motion screenshot of the hero by `docs/make-og-image.mjs` (needs the production copy on :3150); rerun it when the hero changes. `next.config.ts` sends HSTS and serves AVIF then WebP (`qualities` 70 and 75: Next 16 rounds an unlisted `quality` to an allowed one). Headings: one `h1` (hero), an `h2` per section (the principles' lead-in line is its h2), sweep gate G12. Launch steps, Search Console, host redirects and the backlink strategy: `docs/seo.md`.

### Theme, color, type

The site has one theme: **white** (client decision). Three layers, each in one place:

- `src/styles/theme.css` is the **only** file allowed to contain raw color values — twelve tokens: the client's eight, plus four **for the water and the fish only** (D12, client review 2026-10-15): `--color-sea-shallow` (#4bb7e4, the light azure where the sun reaches), `--color-sea-mid` (#1c8ccb, the azure most of the sea is), `--color-sea-deep` (#0b2f6e, the navy of the deep) and `--color-brand-blue` (#2874e4, sampled from the logo's waves, for the fish). The sea is the client's own **reference photo of the ocean** (azure and cyan, navy, white foam), read by eye for now: to lock the exact hexes save the photo as `docs/ocean-reference.jpg` and run `node docs/sample-ocean.mjs docs/ocean-reference.jpg` (k-means over the water pixels, foam left out, prints the candidates for the three sea tokens). Roles: `--water`, `--water-mid`, `--water-deep`, `--fish` (`roles.css`); lint `sea-scope` keeps them out of text and out of every file but the water and fish ones. The blue fish on blue water need a dark back, a pale belly and a thin sunlit rim (`renderFish.ts`), and the copy stays AA by light, not by muting the sea (the pool of light behind it, the sunlit shallows under the captions).
- `src/styles/roles.css` maps *roles* (`--page`, `--page-alt`, `--ink`, `--ink-soft`, `--ink-muted`, `--line`, `--accent`, `--on-accent`) onto those tokens. Components use roles (`bg-page`, `text-ink`, `border-line`, `bg-accent`) rather than naming dark or white, so re-theming is a change in this one file. `globals.css` exposes roles and tokens to Tailwind through `@theme inline`; Tailwind's default palette and stock shadows are wiped (`--color-*`, `--shadow-*: initial`).
- Tailwind scans only `app/`, `components/` and `lib/` (`@source` in `globals.css`, `source(none)`): scanning the repo would pull the example classes in `.agents/` (raw `rgba()` shadows) into the compiled CSS. After a build, the compiled CSS should hold only the token hexes (eleven distinct values, `#00b2ff` is two tokens; plus Tailwind's `#0000` = transparent).
- Canvas code reads the same tokens at runtime via `lib/theme/brand.ts` (`readBrandPalette()`: `alpha()`, `solid()`, `rgb()`), which resolves the CSS custom properties. That file holds the one `rgba(` string builder.
- Type is Raleway only, configured in `lib/config/fonts.ts` (`next/font/google`, variable font, `--font-raleway`); `globals.css` maps `--font-sans` to it. There is no other font and no mono. Raleway's default digits are old-style, so the body sets `font-variant-numeric: lining-nums`.
- The logo's source is `public/images/mechaavo-logo.jpeg` (two waves plus the MECHAAVO wordmark; off-palette blue and a red E). The client asked for it exactly as supplied, so it is shown in its OWN colours (the one asset exception to the eight tokens; CSS and canvas stay token-only): `docs/make-logo-assets.mjs` turns the JPEG into true-colour transparent PNGs (`mechaavo-logo-mark.png`, `mechaavo-logo-lockup.png`) and a white-square favicon (`app/icon.png`), and `components/brand/BrandLogo.tsx` renders them with `next/image`. The hero nav and the story section both show the full lockup (waves plus MECHAAVO wordmark; the nav logo is at most 128 px wide, `.hero-nav__logo`, so the bar stays at most 80 px). The mark's alpha is still the faint watermark behind the story headline (filled with a token). Under 768 px the three nav links fold into a Menu button (`HeroNavigation.tsx`: Escape, outside press and link click close it) because they cannot sit beside the logo; without script the CSS lays them out as a row under the logo instead. To change the logo, replace the JPEG and rerun the script (then update the two `aspect-ratio` values it prints in `src/styles/brand.css`).

### Heading system (Tide)

Every heading on the site is one system: `components/ui/Tide.tsx` (markup, no hooks, works in server and client components), `src/styles/tide.css` (look and motion), `components/ui/TideObserver.tsx` (a leaf mounted once in `app/page.tsx`). Use it for any new heading instead of colouring text by hand.

- **Colour, within the 8 tokens.** On white the brand blues are 2.4:1 and 1.9:1 and cannot carry text, and the letters stay dark; colour comes in around them. (1) The **plate**: the payoff word of a heading sits on an **ink label** skewed -9deg, white type on it (19:1), one cyan edge along its foot and a tinted lift (no glow): `--plate-bg` (`--ink`), `--plate-ink` (`--page`), `--plate-edge` (`--accent`) on `:root` in `tide.css`, the one place to tune it. (Client review 2026-10-15, checked against the taste skill, 4.2 and 9.A, and ui-ux-pro-max: the first plate, a gradient between two near-identical fully saturated cyans, read as flat neon and on the new azure water was the same hue as its ground and dissolved; the ink label stands off every ground the site has, water, white page and gray band, at 9 to 18:1 measured, and the cyan edge is the one accent used with restraint. Four candidates were rendered and compared on the hero and a white section.) (2) The **letters** are ink dipped in the water: a vertical gradient from `--color-dark` toward `--color-primary` whose blue stop lies past the end of the glyphs, so the baseline only gets about 40% of the way (5.9:1 and better measured at the baseline). A quieter second line uses `--color-secondary` at 84%. (3) The **drop**: the full stop is a blue circle that falls onto the baseline, squashes, springs back, and sends two flat ellipse ripples in `--color-accent-secondary` (the lure's splash, in miniature).
- **Markup.** `<Tide as="h2" text="Great products don’t happen by chance.|They are engineered with [purpose]." drop muted={[1]} />`: `|` is a line break, `[words]` the plate, a final `.` becomes the drop when `drop` is set. Words are real inline text with real spaces (copy, find-in-page and screen readers read plain text); the plate and drop are `aria-hidden`. `Mark` and `Drop` are exported for hand-built markup (the hero lines, whose arrival is CSS from first paint and whose `data-hero` hooks the scroll timeline moves).
- **Motion** (transform and opacity, plus one paint-only custom property): words rise out of their masks (`clip-path`, not `overflow: hidden`, which would move the baseline) 55 ms apart; the plate wipes in behind the payoff word; a glint of light crosses it once; the drop lands; the water level in the letters (`@property --tide-dip`) rises. Plays once, when the heading first scrolls into view (`TideObserver` sets `data-inview`); hovering a landed heading on a pointer device replays the glint and ripples. Nothing loops.
- **Starting it.** The observer for headings on the page; `inview` for one that appears on demand (the inspector's name); `manual` for one shown by something other than scrolling: the catalog's heading waits until the card is half open (`categoriesTimeline.ts` sets `data-inview`; the component's load-failure path sets it too). The hero title starts with `data-inview` from first paint; the hero statement's plate and drop start off `data-caught`. A plate that opens a line hangs into the margin (`tide__mark--lead`) so the text keeps the column's edge.
- **No text morph.** A morph of the plate words (letters resolving into the real word as the plate wipes in) was built and shown on 2026-10-16 and then taken out again at the client's word: "we are messing it up with the word transformation, better to keep it as it was before". The heading motion is exactly the one above; a timer-driven word-cycling component (componentry.dev's Text Morph) had been reviewed earlier and not taken either (an infinite loop on headings, no reduced-motion or aria story, a license to verify). Do not add word or letter transformations to headings without asking.
- **Fallbacks, each tested.** No script, or reduced motion: every heading is finished (plates open, drops down, nothing held back). Held back only under `(scripting: enabled) and (prefers-reduced-motion: no-preference)`. If hydration fails and the observer never starts, a CSS failsafe shows every heading after 3 s (`html:not([data-tide-ready])`). Forced colours: system colours, no gradient. A heading's real `color` is still ink, so tools and forced colours see ink.
- **Verified 2026-10-02:** 38 checks (behaviour, static fallbacks, failsafe, pixel-measured contrast, no overflow from 320 to 2560 px, CLS 0.0000 while every heading plays); Lighthouse accessibility 100 on mobile and desktop.

### Button plate (the "cast" plate on every button)

Every button wears a plate on hover (the buttons' own cyan one: since 2026-10-15 the headings' plate is an ink label, and the buttons keep the cyan wipe as their hover state): `src/styles/tide-button.css`, class `tide-btn`, no markup, no JS. The button's `::before` is the plate (same gradient, `--tide-skew` and curve as the headings; `--tide-skew` now lives on `:root`), its `::after` the glint (Tide's `tide-glint-again` keyframe); `overflow: hidden` clips both to the button's own shape. Hover, keyboard focus, a press, or (menu button) `aria-expanded="true"`: the plate wipes in over 420 ms, the glint crosses once after it lands, the label turns ink (white on the blue plate is 2.4:1, ink on it 8:1). Leaving retracts the plate the way it came in 260 ms (no origin switch, so an interrupted hover never jumps). Timings are tokens at the top of the file (`--btn-in`, `--btn-out`, `--btn-ease`, `--btn-color`).

- **Rules for a new button:** add `tide-btn`; make sure it is positioned (the static ones set `position: relative` in their own rule, because a `position` in the shared rule would beat Tailwind's `absolute`); if it has its own `transition` list keep `color var(--btn-color)` in it (otherwise the label flips before the plate covers it); put no `:hover` background of its own on it (the plate is the hover). Keep each button's own lift or `:active` push (hero CTA lifts, the rest scale to 0.96-0.98).
- **Touch:** `:hover` is only used under `(hover: hover)`, so a tap never leaves a stuck plate; on touch the plate shows on `:active` and while the menu is open. Reduced motion: no wipe, no glint, the plate fades in over 150 ms. Forced colours: no plate, a `Highlight` outline. No script: unchanged (CSS only).
- **Who wears it:** hero CTA, the four nav links (padding with an equal negative margin, so they sit where they did), the mobile Menu button, the modal's close and Done buttons. **The hero CTA wears the heading's INK plate at rest (`var(--plate-bg)`, white type, `var(--plate-edge)` foot edge; `underwater.css`), matching the payoff word "cast" in the headline above it, and plays the glint hover animation (`tide-glint-again`). The nav's links and Menu buttons (the hero's and the sticky bar's, one nav in two states) wear the heading's INK plate on hover, not the cyan one** (`tide-button.css`, `:is(.hero-nav, .site-nav) .tide-btn`: white label on ink with the accent edge along the foot; client round 3: the hero nav sits on the water, whose azure is the cyan plate's own colour, so its hover was lost and the links "blended with the background"): the links are also full `--ink` at weight 700 (they were `--ink-soft` 600), the hero nav has a thin veil of the page's light behind it (`.hero-nav::before`, fading to nothing), and the shown sticky bar has a soft lift under it so it does not melt into the pale azure `#story` opens on. The category tiles keep their lift and border and put the heading plate (ink, white type) on the **name's last word** (Tide's `Mark`, closed until the tile is touched; the word is ink on the tile until the plate covers it and then turns white with it; `categories.css`). The logo link is an image, not a button, and keeps its bubble stream.
- **Not added on purpose:** the drop and its ripples. Wipe, glint and the label flip already carry the state change; more would be motion for show.
- **Verified 2026-10-02 (clone build):** every button hovered frame by frame (wipe, glint, ink label, retract), rect identical hovered vs not (apart from each button's own lift), CLS 0, keyboard Tab through all, touch (no stuck hover, `:active`, menu open / close), reduced motion, forced colours, no script, nav one line and CTA one line from 320 to 2560 px, Lighthouse accessibility and best practices 100 on mobile and desktop, compiled CSS still only the token hexes (eight at that date; twelve tokens since 2026-10-15).

### Hero system

The hero is a cinematic, scroll-driven underwater scene in the client's ocean (D12): pale sunlit azure at the surface (upper left, where the nav, kicker and headline sit), a pool of light behind the lede and the call to action, the azure body of the sea, navy gathering to the right and below, sunlit shallows and a lit seabed at the lower left where the captions sit in ink; the fish are Mechaavo blue, countershaded with a sunlit rim. The column is an opaque water gradient (`.hero-bg`), not a tint on the white page. Concerns are kept deliberately separate:

0. **Sticky track, no JS pin; the catalog rises through the hero (client review 2026-10-16, round 3).** `MechaavoHero` renders `.hero-track` holding, in order: the hero (`position: sticky` only under `(scripting: enabled) and (prefers-reduced-motion: no-preference)`, else static), `.hero-spacer` (the story's scroll distance: `(--hero-screens - 2 - --sheet-lead) * 100svh`, 1.15 screens landscape, 0.85 stacked; `--hero-screens` 3.9 / 3.5 and `--sheet-lead` 0.75 / 0.65 on `.hero-track`, `underwater.css`; `--sheet-lead` was 0.55 / 0.45 until round 3d, see the scroll budget below), its `children` (the categories: `app/page.tsx` passes `<ProductCategories />`), and `.hero-tail` (one more screen, given back by the track's `margin-bottom: -100svh`: a sticky element only stays stuck while its track's content can hold it, so without the tail the hero scrolled away under the catalog's last screen; with it the hero stays pinned to the catalog's very end and `#story`, painted later, comes up over it). `#categories` lands 0.2 of a screen earlier than the old curtain's top did (round 3d), so the bite and the reel did not move but the list comes sooner. There is **no sheet and no swell any more** (the white sheet with an SVG wave read as "a messy hilly overlay"): the catalog is transparent once the timeline runs (`.hero-track[data-backdrop]`, set by `heroTimeline.ts`) and the hero is its **live backdrop**. The story is scrubbed over `(--hero-screens - 2)` screens read from the track's computed style (`scrub` is 1 s, 0.4 s on a coarse pointer: `lib/animations/scrub.ts`). A second scrubbed trigger, from the catalog's top entering the screen over one screen of scroll (a fixed length, independent of the catalog's height), is the **camera sinking**: one number, `sink`, written only to properties nothing else animates (each `.hero-ray`'s own `translate` and `opacity`, `.hero-caustics`' `translate`, the new `.hero-depth` layer's opacity (`--z-depth`, a gradient from the mid azure thinned with the deep to the deep, opacity `0.92 * smoothstep(0.1, 0.5, sink)`: the catalog's white heading is read on it), the `.hero-captions`, `.hero-lure-fade` and `.hero-nav` boxes' opacity, and `--leave` on `.hero-statement-slot`, read by `.hero-statement-fade` and the slot's wash: the slot's own opacity is the catch's) and to `scene.sink` (the engine adds `0.4 * sink` to `descend`; the seabed's foot is 24% so its edge never shows). Text leaves by opacity only (`leave = 1 - 3.5 * sink`: the hero's dark ink words, nav and lure are gone by a quarter of the way in, before the water deepens). At the **handover line** (`lib/utils/handoverLine.ts`: the larger of the bar's height plus 2% of the screen and 65% of the screen; shared by `SiteNavigation` and the timeline) the sticky bar slides in, the hero turns `inert` and `scene.backdrop` is set, so exactly one nav is exposed and it is never an invisible one; when `#story` covers the whole hero `scene.covered` is set and the engine rests. A jump to a section (`sectionJump.ts` dispatches `section-jump` after the hash change) brings both scrubs to the new position at once, so the catch and the statement do not play out behind the glass after the veil lifts. Reduced motion and no script: no spacer, no tail, no pinning, a still hero followed by a white catalog with white plates (sweep's static check: no spacer, not sticky). The track's ground is the floor of the water (it shows only where a phone's toolbars hide and the screen is taller than the 100svh hero).

**Scroll budget (sweep gate G16).** After the bite the story is short on purpose. Every beat before the catch is the old 4.1-screen story's, scaled by 2.15 (`STORY` in `lib/underwater/story.ts`, including the fish's own thresholds `notice`, `windup`, `strike`, `hysteresis`), so the approved bite lands where it did (0.88 screens down on a laptop, 0.75 on a phone, with the scrub's lag); the lure is drawn up from a quarter screen after the bite (`reelStart` 0.45 to `reelEnd` 0.82 of the story, lift curve `pow(reel, 1.25)`, the fight gate opens at 0.9 s) and the categories sheet follows (its edge comes up about 0.4 to 0.5 screens after the bite, the first row of tiles is surfaced about 0.9 to 1.1 after it, all eight about 1.4 to 1.5). `heroTimeline.ts` still reads its positions as the old 100-unit authoring and maps them (`at()`, `span()`) onto the new story. Measured with a steady gesture (an eighth of a screen every 250 ms), laptop / phone: bite to the lure drawn up 0.25 / 0.13 screens (was 1.25 / 1.0), bite to the categories sheet edge 0.50 / 0.38 (was 2.02 / 1.75 with the opening card; 4.23 / 3.45 before the budget), to the first row of tiles 1.12 / 0.88, to all eight 1.50 / 1.38. If you change a track length, `--sheet-lead` or a beat, run the sweep's G16 and `npm run test:ui`. **Round 3d (client: "too much scroll just before the category list", 2026-10-16):** the catalog now rises through the hero rather than a sheet over it, and `--sheet-lead` went from 0.55 / 0.45 to 0.75 / 0.65 (landscape / stacked), so the catalog's top comes up about 0.2 of a screen sooner. Measured on a steady gesture (an eighth of a screen every 260 ms): laptop 1440 x 785, bite to the catalog's top entering 0.50 to 0.38 screens, bite to the first row complete 1.13 to 1.00; phone 390 x 664, 0.50 to 0.13 and 0.88 to 0.63. A bare stretch (no hero words and no plate on screen) never occurs on a scroll down. The sink's own scrub is short (`sinkScrubSeconds()`: 0.3 s, 0.2 s on touch; the story's stays 1 s) so a scroll back up no longer leaves a lagging frame of deep water with the heading low on the screen and the statement already gone (that frame, about 0.4 s long, is what the client captured), and the hero's words leave by 0.36 of the sink (`1 - 2.8 * sink`).

1. **DOM + GSAP (`lib/animations/heroTimeline.ts`)** — one scrubbed `ScrollTrigger` timeline (100 units long). It tweens DOM elements (headline, rays, haze, camera push-in) and the shared `HeroScene`. All elements are located by `data-hero="<key>"` attributes, not React refs or class names. It deliberately does **not** drive the fish, the lure's own motion, the catch, or the brand statement.

2. **Canvas engine (`lib/underwater/engine.ts`)** — framework-free. Reads `HeroScene` every rAF tick; never touches React state. Two stacked canvases (`UnderwaterCanvas.tsx`): a fish is drawn on whichever side of the lure's plane (`Z_LURE` in `pose.ts`) it is on. Far foreground fish are drawn into a small buffer and upscaled (cheap blur): upscale only the drawn region with `imageSmoothingQuality = "low"` (a full-screen "high" resample cost ~70 ms a frame at 2x). Frame order: advance the water's current, step the lure rig and write it to the DOM, measure the lure's anchors, step the fish against that, react to bites, draw. The engine tells the page about the catch with `data-caught` on the hero root (set at the bite, cleared on a release) and about the lure with `data-lure`; the brand statement ("Precision creates possibility") is a plain CSS transition off `data-caught` (`underwater.css`), so it arrives with the bite whatever the scroll speed. It is unseen by opacity, not visibility, so screen readers and search still get the words. While the story sheet fully covers the hero the hero is `inert`, so its nav and call to action take no focus from under the sheet.

3. **`HeroScene` (`lib/underwater/story.ts`)** — plain mutable object (never React state). The timeline writes `story` (0–1 master progress), `engage`, `flow`, `zoom`, `descend`, `copy`, `reel`, `sink`, `backdrop` and `covered`; the engine writes `calm` and `statement`. **Backdrop mode** (`scene.backdrop`, the catalog over the hero): the engine keeps the water alive but draws at most every 32 ms (48 on the phone tier or in lite mode), stepping through all the time that passed; the catch (hooked fish, line, lure glow, its bubbles) eases out over 350 ms (`catchAlpha`) and back in when the reader scrolls up; no frame-rate sampling (the one-way `data-lite` would otherwise trip on the catalog's compositing); it pauses while `html[data-inspector]` (the inspector is open). `scene.covered` (`#story` over the whole hero) stops drawing. `calm` and the fight are on the fish's own clock (time since the bite), never the scroll, so a fast scroll cannot skip or cut short the fight.

**One water current for everything (`lib/underwater/current.ts`).** A slow uneven push (leftward, nose of the lure into it) drives the lure's float, the bow and ripple of its line, the weed (`seabed.ts` draws blades live), the sediment motes (`particles.ts`) and the bubbles, so they lean and ease on the same beat. Do not give any of them a private sway.

**Fish are time-based, not scrubbed.** Scroll only decides *what* the primary fish is doing (`story` thresholds in `story.ts`, with hysteresis); every move is made at the fish's own speed in body lengths per second.
- Sizes come from the lure. The lure is small (about 14% of the width, `.hero-lure-slot` in `underwater.css`); the hero fish is `FISH_TO_LURE` (`lib/hero/lureConfig.ts`) lure lengths long, and every fish at or in front of the lure's depth (mid, near, visitors) is at least a lure long (`fish.ts` sizes tiers in lure lengths). A lure is never bigger than the fish. Do not cap `world.unit`.
- How many fish of each kind there are depends on the screen (`lib/underwater/quality.ts`, tiers phone / tablet / laptop / desktop / wide). The counts and the fish-to-lure ratio are hand-tuned by the client; read them from the file rather than from this note, and if a screen looks cluttered cut big fish, not small ones. Big fish keep a corridor of clear water around the lure (`laneBands` in `fish.ts`); weed density also follows the tier.
- Primary fish (`primaryFish.ts`): `patrol → notice → inspect → circle → windup → strike → hooked`, plus `release` when scrolling back. It swims in from the left edge once the lure has arrived. **Patrol is a stadium-shaped track** on the fish's own side of the lure (a carrot runs round it and the fish follows on a spring): a swim along each straight at 0.36 body lengths per second, a 1.6 to 3 s hover at its end, then a wide slow turn through the camera axis, so the way it faces is always the way it swims and it never needs more turning than `YAW_RATE` allows. The old patrol loop was smaller than the fish (heading wrong in 73% of frames, head flipping 39 times a minute), which read as stuck and unnatural; `circle` is sized the same way (its speed is capped so its peak turn stays at 70% of `YAW_RATE.circle`). `npm run fish:sim` (`scripts/fish-sim.mjs`, the real `updatePrimary` through jiti, no browser) checks heading, turn rate, flips, travel and clearance from the lure for split and stacked layouts: run it after touching the fish brain. **The lure tracks the fish**: the first notch of the wheel sets `scene.lead` rising and the lure drifts down the current to just ahead of the fish's nose (the engine follows the nose while the fish patrols, then holds the spot once the fish notices it; `rig.trackGoal*`). While patrolling, the fish measures its position from the lure's *resting* hook (`PrimaryBrain.frame` 0) so it keeps to its own water; from `notice` on it measures from the live hook (frame 1), re-based so nothing jumps. It bites quickly (notices on the first notches, strikes at about a seventh of the way through the scroll, short dwells). If scroll runs three or more steps ahead it **dashes** (every step hurried until it catches up), so a flick still shows the whole catch in about two seconds. **The bite takes the whole lure**: the strike lands on the belly hook exactly as before (its path and timing are client-approved: do not move them earlier), then for `GULP_SECONDS` of `hookedTime` the mouth slides forward over the lure to just past its nose (`applyFight`, measured live from the lure's anchors; `brain.gulp` 0–1), jaws wide then closing, so the lure ends up inside the fish and the line leaves its lips. On a release `gulp` eases back to 0 and the lure comes back out. The fight feeds the lure rig (`pull`, `shake`). After `STORY.reelStart` more scroll draws the hooked fish **up out of the water** along the line (`scene.reel`; the engine gates it until the fish has fought a while and eases it, so a fast scroll still shows the bite first). The hooked fish keeps a natural, near-horizontal heading (client-tuned in `applyFight`; do not tip it vertical).
- **Foreground colour (client round 3: "the fish in the foreground can be more colour saturated so they can be seen immediately").** The `near` fish had been the logo's blue deepened with the near-black ink token (`BACK`), a grey-navy silhouette that sank into the deep water, and the mid fish were fogged a quarter into the sea. Now the near and mid tiers are the logo's blue deepened with the navy of the sea (`BACK_VIVID`, `BACK_VIVID_SOFT` in `renderFish.ts`: `brandBlue` + `seaDeep`, never `dark`), the near fog is 0.06 into the mid azure (was 0.14 into the deep) and the mid fog 0.14 (was 0.28), and their opacity ranges are 0.76 to 0.92 (near, was 0.55 to 0.75) and 0.80 to 0.94 (mid, was 0.68 to 0.86) in `fish.ts`. The far fish stay faint on purpose (depth), the hero fish are unchanged, and the copy still wins: `textFade` thins any fish over the words. On the deep water behind the catalog the saturated blue also reads, where the grey-navy ones disappeared.
- Ambient fish: lane crossers, baitfish schools, and a visitor on a tilted loop around the lure; speeds 0.45–2.8 body lengths/s, tail beat follows speed, pitch clamped, depth turns only.

**Lure rig (`lib/underwater/lureRig.ts`).** The engine owns the lure's `pull` and `shake` DOM layers plus the jointed parts of `LureArt.tsx`. `pull` carries the whole lure (float, tilt about the nose, size). The lure *floats*: position springs forced by the shared current plus a twitch every 5–9 s, the pendulum tilt, jointed tail wag, hooks on rings. The tail treble is dressed with a feather tuft (`dress` and `dress-tip` parts, nested in the treble, with their own springs: it swings with the treble and flutters on the current's gusts; a worm trailer was tried and dropped, hard baits do not carry one). On arrival it swims in from the nav logo (its waves, `LOGO_MARK_Y` in the engine) along a bezier (small and growing, nose along its path) with a bubble trail and a small splash (`bubbles.ts`: two rings and spray). Anchors ride inside the parts that move them so the fish and the line stay on the real hook. The line (`drawLine` in the engine) is a flexible thread from the nose to a fixed rod tip far up the frame: it bows downstream with the gusts, ripples, sags when slack, goes straight and trembles when a fish is hooked; at least 1.6 px of dark core so it is always visible. Once a fish has drawn the lure into its mouth the lure fades out (`gulp` in `readRigPose`; the two trebles and the feather, which hang outside the fish, fade first): **by opacity only, never size or position**, because the engine measures `lure.length` and the anchors from the DOM every frame and sizes the fish from them. The lure body is fully opaque (solid underlay, no transparent gradient stops) and sits above the caustic light and below the copy. Writes are CSS transforms only. Never animate those layers from GSAP.

**Load order matters for performance.** The headline, nav and supporting copy arrive with CSS keyframes in `src/styles/underwater.css` (transform-only on the text); the lure stays hidden until the engine sets `data-lure` (with a CSS failsafe after 5 s and a no-script fallback). GSAP/ScrollTrigger and the canvas engine are dynamically imported and started when the browser is idle (`lib/utils/idle.ts`), and the caustic tile is built in slices. Do not move the arrival back into GSAP or statically import either. On a throttled phone the Largest Contentful Paint is the tagline re-rendering when Raleway swaps in, so keep first-load bytes and early main-thread work low.

**One motion language across the page (the last-priority review, 2026-10-15).** The user asked whether to "keep the motion graphics throughout the UI" and was unsure. Not carried, on purpose: the canvas, the bubbles and the shaft parallax stay in the hero (a canvas per section is the cost the hero's budget exists to avoid), no new infinite loops (the WaterLight washes keep only the drift they already had; the hero's ambient light is the one registered family, D13), no parallax on text. While a wave runs `data-revealing` turns the plates' own transitions off (a CSS transition outranks an animation). **Fallbacks, each tested:** reduced motion = plates visible, nothing animates; no script = visible; failure to load the module = `data-shown`; a CSS failsafe (`cat-surface-failsafe`) shows every plate after 3 s if `html[data-cat-ready]` was never set; hydration later than 2.8 s with the grid on screen leaves the plates up.
- **The inspector** (`CategoryInspector.tsx`, `categories-inspector.css`, flight in `categoryInspector.ts`): a ledger. The photo, the name (Tide), the strapline, the story, the product line as numbered rows, the specifications as a `dl` between hairlines, the features numbered, and the **sounding column** (the water from the surface down with the category's range lit; lies on its side under the story on a phone, stands beside it from sm). **Morphing Modal:** a ghost (a clone of the plate's photo, fixed over everything) flies from the plate's window to the dialog's photo by transform and a clip-path crop (uniform scale, cropped not stretched, 640 ms), lands, and is replaced by the real photo in the same frame (`data-landed`); the ledger then rises 60 ms apart and the ruler draws. Closing runs it back (see round 3: the whole plate flies, not only the photo) and resolves before the dialog is removed. Escape during the opening finishes the flight and goes back. No flight (reduced motion, no Web Animations, a plate off screen, a photo not loaded) is still a dialog that appears and goes: it never depends on the ghost for state. **It is portalled to `document.body`**: inside the section it sat in the sheet's stacking context, under the sticky bar (`--z-bar` 600), which was cut across the photo; `--z-modal` is now 700, above the bar and the veil, below the skip link. Escape closes, Tab stays inside, focus returns to the plate; `max-height: 90dvh`, `overscroll-behavior: contain`, a sticky zero-height close row `.cat-modal__close-row`, the scrim the page's dark token at 62% with no blur. React runs effects twice in development: `startInspectorMotion` marks itself dead on `cancel()` so a cancelled flight never lands.

### Story section

`components/showcase/BrandStory.tsx` holds three sections with three different layouts, each text block at most 25 words. The first (`#story`) opens with a pale azure (`--story-edge`, defined on `:root`: a `top` water light that cannot see it loses its whole wash) that the categories section above it fades into at its foot; every section has water behind it (`WaterLight.tsx`: `top` = the hero's water clearing into the page with the brand mark as a watermark and the hero's caustic light drifting on it, `soft` on the gray band, `bottom` at the foot of the page: now in the footer). The caustic tile is built by the engine and published as `--caustic-tile` on `<html>` (`data-caustic`); without script the gradients stand alone. The three principles carry Phosphor marks.

**There is no video on the site** (user decision 2026-10-16, after the story panel went on 2026-10-15 and the footage had moved behind the hero and the categories).
